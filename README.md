# 生态治理兵法（governance-playbook）

> 为没有专职治理团队的中小平台/社区，把内容与账号生态治理从"靠感觉删帖"变成"有分级、有梯度、有指标"。

## 为什么做这个

社区营销号删了又来、评论区越来越乱、低质内容淹没优质创作者——大多数中小平台和社区的运营者遇到乱象时，手里没有任何方法论：不知道哪些该自动处置、哪些该人工判断，不知道封禁该分几档，更不知道怎么证明治理是"救了生态"而不是"杀了生态"。

这个 skill 把平台治理的通行方法论（违规双轨分级、账号处置梯度、生态指标三层、治理三节奏）打包成一份可执行的《治理策略包》。

## 快速开始

```bash
npx skills add bonniegeng-max/governance-playbook
```

或直接把本目录复制到你的 WorkBuddy / CodeBuddy 用户级 skill 目录，重启对话即可。

## 用法示例

对话里直接说：

- "我们社区营销号太多，删了又来，不知道从哪下手治理"
- "帮我设计一套违规分级"
- "账号处置梯度怎么定？直接封会不会误伤太多？"
- "UGC 评论区治理方案"

你会收到固定四件套：

1. **违规分级表**——内容轨 + 账号轨双轨 P0-P3，每级含处置时限与处置方
2. **账号处置梯度表**——警告→功能限制→降权→禁言→封禁，每级含回归条件与申诉入口
3. **治理优先级**——先治什么后治什么，每项附理由
4. **生态健康指标看板**——北极星/健康度/干预三层，必含误伤率

## 边界声明（与能力同样重要）

- 不做单条内容"能不能发"审核（创作者侧工具的活）
- 不做限流申诉、反作弊模型代码、海外法规合规（DSA/OSA）
- 不提供任何对抗平台现行规则的战术示例；此类请求一律拒答转介
- 不硬承诺治理效果——只给方法与观测指标
- 涉违法内容：指官方举报通道

## 判例机制（边用边厚）

当前 v0.1.0 的知识内核基于公开方法论（ROOST/PwC/WebPurify 等）。每次真实使用后说"存判例"，本次判断与实际效果会按模板入库（`references/案例库-判例.md`）——判例库越厚，策略越贴你的平台。判例入库执行脱敏一票否决。
