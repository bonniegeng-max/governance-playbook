# 案例库-判例

> 何时读：出方前查本平台先例 / 用户说"存判例"时写入。
> **当前状态：空（0 条）**——按设计，公开方法论打底，判例持续灌注。判例库为空时，输出必须声明"基于通用方法论，缺本平台判例支撑"。

## 灌注方法

每次真实使用后，用户明确说"存判例 / 记录这次"时，按以下模板追加（未经明确要求不写）：

```markdown
### 判例 N：<一句话标题>
- 日期：
- 平台/量级：
- 乱象描述：
- 当时的判断与依据（引用哪份 reference 的哪条规则）：
- 实际结果（处置效果 / 误伤情况）：
- 复盘结论：
- 可复用规则（一句话，冲突时优先于通用方法论）：
```

## 灌注纪律

1. 一条判例必须含"实际结果"——只有判断没有结果的记为"待验证判例"，单独标注
2. 判例与本平台强相关（量级/类型匹配）才可直接引用，否则降级为"参考判例"
3. 与通用方法论冲突的判例要显式声明覆盖关系（判例优先，注明原因）
4. 脱敏一票否决：真实姓名、机构名、内部数据不入库（公开报道案例标注"公开案例"来源属性）
