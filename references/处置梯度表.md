# 账号处置梯度表

> 何时读：设计账号处置与申诉体系时。来源：zeroes-ones 术语体系 + WebPurify，重构转写。

## 梯度链

```
警告通知 → 功能限制（发频/可见范围）→ 限流降权 → 禁言 → 封禁
```

设计要点：
- 每级配**明确回归条件**（如"30 天无再犯恢复一档"）——梯度对轻度违规者必须有回归路径
- 配套**账号分层**：新号观察层 / 正常层 / 优质层（优质层可豁免部分机审）
- **误伤回滚**必备：处置错了有明确恢复与致歉机制
- **静默限流（shadowban）是反模式**：用户不知情、不知因、不知何解，信任杀手——要限流就通知

## 账号完整性威胁谱

| 威胁 | 识别信号 | 处置倾向 |
|---|---|---|
| Credential stuffing（撞库） | 同源 IP 多账号登录尝试 | 账号安全通道，非治理梯度 |
| ATO 账号接管 | Impossible travel（不可能行程）+ 设备指纹突变 | 冻结 + 原主验证 |
| Bot 批量注册 | 一次性邮箱、注册轨迹雷同 | 注册层拦截 |
| CIB 协同性虚假行为 | 图关系聚集、内容相似、同批创建 | 团伙级封禁 |
| Fraud rings 欺诈环 | graph-based 账号关联图 | 团伙级封禁 + 关联图扩展排查 |

区别于普通违规：威胁谱类是**敌方**，走拦截/冻结/团伙封禁；普通用户违规走梯度链。

## Graduated response（分级响应）

WebPurify 概念 **democratized deception（平民化欺骗）**：普通人用廉价 AI 做轻骗局（假截图、修饰履历），投入低成本不再等于恶意深。**普通用户首次轻违规 → 梯度前段（警告+教育）**，不套重刑——把用户群推到对立面是治理的自毁。

## 申诉闭环（appeal → reinstatement）

- 每个梯度级都可达申诉，不只封禁级
- 合规处置三件齐：**处置理由 + 证据 + 恢复条件**
- 设计参照 DSA Art 15/24/42 透明度要求：处置可解释、可统计、可外报（本 skill 不做合规咨询，仅作设计参照）
- 申诉成功率 <10% 时优先检查：申诉入口用户能不能找到

## 反模式

1. 一刀切封禁治营销号（误伤正常用户，且号源便宜封不完）
2. shadowban 不告知
3. 无申诉通道的不可逆处置
